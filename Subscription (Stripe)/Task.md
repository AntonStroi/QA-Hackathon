# Перевірка життєвого циклу підписки Stripe
***Завдання:*** Уявіть, що вам потрібно протестувати процес підписки на сервіс, реалізований через Stripe Checkout Payment Link та Stripe Customer Portal. В рамках цього завдання налаштовано продукт з двома рівнями підписки. Для цього продукту створено Payment Link  (посилання на оплату), який дозволяє клієнту оформити підписку із застосуванням промокодів. Деякі промокоди дійсні лише для конкретного продукту або тарифного плану, інші — для кількох продуктів. Stripe Customer Portal  увімкнено у тестовому режимі, що дозволяє користувачу керувати своєю підпискою після покупки (скасовувати, змінювати план тощо). Ваше завдання — перевірити весь життєвий цикл підписки – від придбання зі знижкою до зміни плану та скасування – використовуючи лише веб-інтерфейс Stripe.

***Ключові кроки:***

- Покупка підписки через Payment Link.
- Валідація промокодів. 
- Скасування підписки через Customer Portal.
- Зміна плану (оновлення підписки на іншу).
- Пауза та поновлення підписки.
- Відновлення підписки після завершення 

***Інструменти:***

- Тобі знадобиться: браузер, GitHub акаунт.

# Завдання 
Потрібно протестувати процес підписки на продукти. В рамках цього завдання налаштовано два продукти:
- Premium Access
- Premium Access Plus

Premium Access можна проапдейтити до Premium Access Plus. Для цих продуктів створено [Payment Link](https://buy.stripe.com/test_6oU9ATa0K2TxdN1fs0gA801), який дозволяє клієнту оформити підписку із застосуванням промокодів:
- promo code: ONLYTEST - 10% діє тільки для продукту Premium Access
- promo code: QAFRIENDS - одноразовий, доступний для двох продуктів Premium Access та Premium Access Plus

# Що обов'язково потрібно протестувати
1. **Покупка підписки через Payment Link.** Перейдіть за наданим Payment Link та оформіть підписку на продукт у тестовому режимі, використовуючи тестову картку. 
2. **Валідація промокодів.** Протестуйте дію двох типів промокодів: 
- ONLYTEST - 10% діє тільки для продукту Premium Access; 
- QAFRIENDS - одноразовий, доступний для двох продуктів Premium Access та Premium Access Plus.
3. **Скасування підписки через Customer Portal.** Після успішної покупки зайдіть до Stripe Customer Portal як клієнт.  Перевірте можливість скасувати підписку через портал: 
- Ініціюйте скасування підписки та оберіть варіант негайного скасування. Переконайтеся, що дію виконано успішно – статус підписки у Dashboard змінюється на canceled.
4. **Зміна плану (оновлення підписки на іншу).** Перевірте можливість оновлення підписки з одного тарифного плану на інший через Customer Portal: 
- Увійшовши як клієнт до порталу, знайдіть опцію Upgrade для своєї активної підписки. Спробуйте змінити план з Premium Access на Premium Access Plus. Переконайтеся, що портал дозволяє обрати новий план та показує коректну інформацію про нову ціну перед підтвердженням.
5. **Пауза та поновлення підписки (якщо підтримується).** З’ясуйте, чи доступна клієнту функція призупинення підписки через Customer Portal?
6. **Відновлення підписки після завершення (reactivation).** З’ясуйте, що відбувається, якщо підписка була скасована або повністю завершилася (наприклад, минув оплачений період після cancel_at_period_end). Що робити користувачу, якщо він бажає продовжити користування сервісом?

***Requirements:***
- Payment method використовувати Card.
- Після оплати вас автоматично перенаправить на [Stripe Customer portal](https://billing.stripe.com/p/login/test_9B68wPa0Kcu74crenWgA800) 
- Stripe Customer Portal  увімкнено у тестовому режимі, що дозволяє керувати підпискою після покупки (скасовувати, змінювати план тощо). 
- Тестувати крос браузерність не треба!
- Simulate a successful payment for a specific card brand - не треба!
- Simulate successful payments from specific countries - не треба!
- Simulate Disputes and Fraud payments - не треба!

Рішення залити на github у папку ***Subscription.*** Воно повинно включати всі необхідні  відео файли (не довші 1 хвилин, назва відео співпадає з тестом - покупка, валідація промокодів, скасування, зміна плану тощо), а також додаткові тестові артефакти, на які спиралися при тестуванні. ***Чим повніше, структурованіше і водночас простішим для сприйняття буде оформлення ваших результатів — тим легше буде зрозуміти, як саме ви підходили до тестування,*** які сценарії були покриті та наскільки якісно виконано завдання. 

***Врахуйте, що відео файли не мають бути занадто великими! Якщо вже так сталося - заливайте їх у cloud (Google drive, Dropbox тощо) і додавайте посилання на них у github з результатами виконаного завдання.***
